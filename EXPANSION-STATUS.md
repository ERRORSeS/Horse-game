# Persistent care and sales integration

The existing Training 2.0 narratives, exercise identifiers, builders, original discipline skills, independent riding attributes, assessed potential and genetics are retained. Previously fixed training progression was audited rather than rewritten.

## Implemented phases

1. Pure deterministic health and sales engines: additive medical truth and history, observations, relevant diagnostics, treatment courses, recovery, prescriptions, vaccination records, hoof care, persistent listings and atomic transfers.
2. Runtime integration: legacy-save backups before migration; veterinary conversations; medical shops and receipts; individual rescue profiles; contextual owned crops/spurs; seller tack and actual fit; optional trials through the existing riding RPG; PPE, negotiations, contracts, payment and transport.
3. Interface feedback: Town shops share the tack-shop presentation; sales cards and conversations fold; conversations can be hidden/restored without changing financial or ownership records; new listings appear first; seeded market windows last one to ten months, with higher ability tending to sell faster. Rescue placement windows last thirty to one hundred fifty days, display calendar dates and preserve departed listing history.
4. Targeted fixes: all native prompt calls replaced by inline forms, including both horse-selling buttons; seller replies update inline without a full redraw; focus restores without scrolling; completed warm-up allows progression while retaining other safety restrictions; visible wound markers exclude hidden conditions and healed wounds.

Severity outcomes use the user-approved 80:14:13:7 relative weights after an existing opportunity. Opportunity rates are unchanged. Medical values are game mechanics; no player-calculated doses or injection directions are provided.

## Verification

- 26 pure-engine tests, including seeded probability distributions, repeat-event guards, hidden truth, diagnosis relevance, receipts, prescriptions, recovery, farrier care, vaccinations and transaction atomicity.
- 14 integration checks against actual index script order, including migration, fractional skills, canonical exercises, trials, seller schooling/tack, optional equipment transfer, dates, visible wounds and rescue deadlines.
- 139 grouped existing regression checks across ten suites: auto training, calendar, progression, management, pasture, quality of life, training roster, Training 2.0 extensions, small fixes and main training.
- Syntax checks pass for all 24 JavaScript files. No native prompt calls remain in application JavaScript.
- Browser checks on localhost: both sale buttons open inline forms without a new error. Reload retains the user's five horses, calendar and balance. Seller replies previously verified with unchanged viewport position. Rescue placement dates render in day/month/year.

Run with `npm test` using Node.js.

## Remaining limits

This is a reviewable integration phase, not a claim that every line of the original extensive design specification is complete. Expanded narrative pools, the full infection/exposure and recurrence design, all specialized fear triggers, exhaustive manual verification of every transaction combination, and native mobile Safari verification remain future acceptance work. Existing save backups and histories must be retained during further testing.

## Sale-health and seller-reply adjustment

New NPC sale horses receive a seeded 40% pre-existing issue opportunity, with 30% minor, 50% moderate and 20% major severity conditional on being affected (12%, 20% and 8% of all newly generated horses respectively). Existing processed or owned horses are not rerolled. This setting is separate from daily injury opportunities. A 20,000-horse seeded test verifies rates, persistence, valid diagnoses and no automatic disclosure. Seller loading profiles and alternative replies persist; medical and competition wording uses available confirmed diagnoses and actual result records.
