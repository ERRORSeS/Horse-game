# Rider Realism and Horse Behavior 1.0 implementation report

1. **Optional mode.** Settings → Rider Realism is collapsible and defaults off for old saves. Difficult Stable Storylines has an independent switch. Both can be disabled with pending scenes; existing gameplay resumes without optional penalties.
2. **Existing training engine.** The layer extends `t2probability`, `t2attempt`, `t2finish`'s existing caller flow, `renderTraining`, the existing competition chance/resolution functions, and loading/travel actions. It does not introduce a replacement training engine or reward table.
3. **Natural and learned spookiness.** Saved natural spookiness is initialized deterministically from the horse identity with existing personality/trait hints. Learned spook sensitivity is independent and changes through events. Ordinary sessions never rewrite nature or genetic potential.
4. **Temperament.** Intensity is independently initialized, described in five ranges, and editable only in the roleplay settings. It contributes to compatibility and reactions without treating reactivity as aggression.
5. **Rider experience.** Five overall levels and seven editable technique abilities contribute to a cached rider-error calculation. Discipline experience uses the existing SHOW_LEVELS registry. Over-level mistake-risk additions are 0/5/10/18/25 percentage points; no new rider-based entry gate is added. Professional riders retain a nonzero error risk.
6. **Refusals.** Existing fence outcomes, penalties and round plans remain authoritative. Optional behavior adjusts existing outcome chances; no second refusal roll is used. Actual refusals pause progression for reassessment. Suspected causes include timing, balance, conflicting aids, filler, learned avoidance, confidence, fatigue, difficulty and possible discomfort.
7. **Learning.** Meaningful results update separate confidence, trust, avoidance, anticipation, arena and handling values. Ordinary confidence changes are small and daily-capped. Context memories are limited to twelve. Ordinary history retains fifty entries.
8. **Recovery.** Appropriate completed exercises gradually restore confidence and reduce avoidance. Recovery observations use actual outcomes and previous memories. A simpler exercise choice changes the next task; it does not instantly cure fear. Natural temperament remains intact.
9. **Collection.** Collection Confidence is distinct from technical Collection skill. Contact stability and learned comfort affect execution through existing probability/scoring modifiers; existing technical skills and genetic ceilings are not reduced.
10. **Misconduct.** Explicit crop/spur punishment choices are available only with both options enabled and suitable equipment available. Competition equipment rules are respected, with phase-aware dressage defaults. Misconduct is identified as mistreatment, stops ordinary work, recommends assessment, records consequences and grants no extra skill/obedience reward. It is not randomly assigned to the player.
11. **Permanent welfare records.** Meaningful welfare and management entries are separate from the trimmed recent log. Repeating the same current scene does not add another event. Roleplay narratives remain non-graphic and provide no instructions for inflicting harm.
12. **Horse traits and NPC trainers.** Existing personalities and traits remain active. Patient/Fair/Ambitious/Demanding/Inexperienced/Negligent/Abusive NPC characterization is separate from the rider profile. Rare, contextual trainer concerns support reassessment, intervention and changing instructors; later results can record improvement under revised management.
13. **Interactive/Quick/Auto.** Interactive scenes resolve by clicking choices. Quick and Auto work reuse actual Training 2 attempts and aggregate ordinary behavior learning/narrative summaries per session. No new hourly scan or psychological simulation is added.
14. **Competitions.** Showjumping, dressage, hunters and eventing use existing outcome chances and scoring. Quick Compete receives the same behavior modifier with per-entry result caching. Existing eventing phase order, first-round results, pole calibration and jump-off qualification remain unchanged. The layer does not reset jump-off warm-up state. Loading uses existing response weights and actual attempts, without another outcome roll.
15. **Saves and crash repair.** Rider settings, natural/learned scales, memories, histories, incident state and event identifiers serialize with the existing save. Old saves initialize conservatively. A missing active show session is restored to a usable preparation session; already recorded results route back to results rather than being rerolled. Null style lookup safely returns Balanced.
16. **Validation.** The full npm test command includes the new Rider Realism suite. Its checks cover all 128 unique supplied narrative definitions through eligible idempotent event resolution, default/off equivalence, pole-plan preservation, bounded learning and recovery, class equipment rules, actual interactive/quick/auto attempts, cached Quick Compete, persistent state and usable missing-session recovery. The full `npm test` run completed with exit code 0, including the added suite. Targeted Rider Realism checks also passed after the final assessment-link addition.
17. **Files.** `rider-realism.js`, `rider-narratives.js`, `show-session.js`, `index.html`, `package.json`, `tests/rider-realism.test.cjs`, `tests/benchmark-rider-realism.cjs`, and this report. Bond, QOL, genetics, ownership, Sales, auctions and breeding implementations were not edited.
18. **Practical limits.** Narratives are conditional observations, not diagnoses or guarantees. Rare trainer stories are intentionally sparse. Not every quote is expected in a short play session. Performance measurements below are VM microbenchmarks, not a guarantee of end-to-end browser latency on every device. Histories render lazily in ten-record pages; permanent welfare archives can grow over a long-running save.

## Browser verification

An isolated browser save displayed default-off settings, enabled Rider Realism, edited Timing to 28 and saved successfully. A deliberately missing show RPG session recovered without a browser error. Further verification and full-suite status are included in the PR description.

## Measured profile work

The benchmark exercised 1,000 existing probability-profile calls, median of three runs: mode disabled 1,397.91 ms; enabled 1,231.22 ms. These ran alongside regression work and are subject to scheduler/JIT effects; the apparent speedup is not a performance claim. No new per-hour horse scan was introduced.

The final browser check recovered a deliberately missing RPG session into preparation, started course-walk/warm-up preparation, and resolved a real competition choice with no captured browser errors.
